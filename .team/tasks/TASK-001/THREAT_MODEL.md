# THREAT MODEL — TASK-001

> Profile: web. References: OWASP Top 10:2025, ASVS 5.0, API Security Top 10.
> Sources verified: `.team/tasks/TASK-001/EXEC_PROMPT.md`, `.team/tasks/TASK-001/SPEC.md`, `.team/tasks/TASK-001/ARCH.md`, `.team/tasks/TASK-001/PLAN.md`, `.team/DECISIONS.md`, `AGENTS.md`, `.team/project.yaml`, `package.json`, `next.config.ts`, `src/app/layout.tsx`, `src/app/page.tsx`.

## 1. Assets
- **IQD Pricing & Catalog Invariant Integrity:** Single fixed positive integer Iraqi Dinar prices (`priceIqd`), strict 10-product catalog count (`CATALOG_PRODUCT_COUNT === 10`), unique IDs (`"1"`–`"10"`), and mandatory non-empty Arabic product fields (`EXEC_PROMPT.md` R2, R4–R6; `AGENTS.md`).
- **Visitor Browser Execution Integrity (DOM / Same-Origin Asset Surface):** Safe HTML/RSC rendering on `/`, `/products/[id]`, and `not-found` views, plus static local vector graphics under `public/images/products/*.svg` served from the application origin.
- **Non-Commerce & Synthetic-Data Scope Boundary:** Guarantees that zero shopping cart, checkout, payment/COD keys or forms, authentication/session endpoints, database access, or real PII (names, phone numbers, street addresses) exist or reach clients (`EXEC_PROMPT.md` R3, R9, §7; `AGENTS.md`).
- **Routing Determinism & Error Hygiene:** True HTTP `404` status (avoiding `200` soft-404 streams under Next.js 16 `cacheComponents: true` + `partialPrefetching: true`) and generic Arabic error copy without stack traces, internal filesystem paths, or `500` crashes.

## 3. Trust boundaries
1. **Untrusted HTTP Client ↔ Next.js Pre-Stream Proxy & App Router (`src/proxy.ts#proxy` ↔ `src/app/products/**`):** All URL path segments (`/products/:path*`), percent-encodings, query parameters, and request headers cross from anonymous visitors into `proxy.ts`, `ProductPage`, and `generateMetadata`. Note: per `sat-security-web` and Next.js 16 `proxy.md`, Proxy alone must not be the sole guard—`ProductPage`, `generateMetadata`, and `ProductsIndexPage` independently enforce allow-listed lookup and `notFound()`.
2. **Domain Validation Layer ↔ Catalog Data & UI Components (`src/lib/products.ts` ↔ `Home`, `ProductCard`, `ProductDetails`):** `validatePriceIqd`, `formatPriceIqd`, `validateProduct`, `validateCatalog`, and `getProductById` enforce numeric, structural, and local-path invariants before any product enters `PRODUCTS` or renders. `getProductById` uses `Array.prototype.find` strict equality rather than plain-object property indexing, isolating `Object.prototype` keys.
3. **Static SVG Delivery ↔ Browser Origin (`public/images/products/*.svg` & `next.config.ts`):** Direct browser requests to `/images/products/product-*.svg` render as `image/svg+xml` in the site's origin; SVG markup and `imageSrc` validation form a script-execution boundary, while `next.config.ts` keeps `dangerouslyAllowSVG: false` and no `remotePatterns`.
4. **Build/Server Environment ↔ Client Bundle & Responses:** Server environment variables, `.env*` files, internal paths, and raw error details must never serialize into Client Components, `NEXT_PUBLIC_*` variables, `PRODUCTS`, or HTTP `404` HTML.

## 5. Abuse cases
Priority order: access control & scope boundaries first, then IQD money/catalog integrity, then input/prototype/SVG injection, then data exposure & error hygiene, then resource abuse & configuration/supply chain.

- **AB-1** (axis: `access_control` · entry: `GET /products`, `GET /products/[id]` (`src/proxy.ts#proxy`, `src/app/products/[id]/page.tsx#ProductPage`, `src/app/products/page.tsx#ProductsIndexPage`) · ref: OWASP A01:2025, ASVS 5.0 V4 · → T5 · SPEC: AC-7, EC-4):
  An anonymous visitor requests missing, unlisted, out-of-range, whitespace, multi-segment, or traversal-like product routes (`GET /products`, `GET /products/`, `GET /products/99`, `GET /products/0`, `GET /products/-1`, `GET /products/%20`, `GET /products/1/extra`, `GET /products/..%2F..%2Flayout`) against `proxy(request)` or directly invokes `ProductPage` / `generateMetadata` / `ProductsIndexPage`.
  **Expected secure behaviour:** `proxy(request)` rewrites to `/__not-found` with HTTP status `404` (never `200` soft-404, `302`, or `500`); direct component/metadata calls trigger `notFound()` (`NEXT_HTTP_ERROR_FALLBACK;404`); rendered `NotFoundView` displays static Arabic text `"المنتج غير موجود"` and a link to `/`, with zero product data, filesystem data, or requested path segments echoed.

- **AB-2** (axis: `access_control` · entry: `src/app/**`, `src/components/**` (`Home`, `ProductCard`, `ProductDetails`, `NotFoundView`) · ref: OWASP A01:2025, OWASP API4/API8 · → T3, T4, T5 · SPEC: AC-8):
  An attacker probes the application routes and UI tree for unintended state-changing or privileged surfaces—such as `"use server"` Server Actions, `src/app/api/**/route.ts` Route Handlers, cart/add-to-cart buttons, checkout/buy triggers, payment or cash-on-delivery forms, or admin endpoints.
  **Expected secure behaviour:** Zero `"use server"` directives, zero `src/app/api/**` route handlers, and zero cart, checkout, payment, or admin controls/routes exist in the repository or in the rendered DOM of `/`, `/products/[id]`, and `not-found`.

- **AB-3** (axis: `authentication` · entry: `src/app/layout.tsx#RootLayout`, `src/app/page.tsx#Home`, `src/app/products/[id]/page.tsx#ProductPage`, `src/proxy.ts#proxy` · ref: OWASP A07:2025, ASVS 5.0 V7 · → T3, T4, T5 · SPEC: AC-8):
  An attacker inspects storefront responses and components for unintended login/registration flows, session-cookie issuance (`Set-Cookie`), or hidden authentication bypasses (`cookies()` / auth headers) on a store specified as strictly login-free.
  **Expected secure behaviour:** No login, signup, or account UI exists in any view; no `cookies()` reads or `Set-Cookie` headers are emitted by `proxy.ts` or page components; all catalog and details routes operate strictly as public read-only views.

- **AB-4** (axis: `business_logic` · entry: `src/lib/products.ts#validatePriceIqd`, `src/lib/products.ts#formatPriceIqd` · ref: OWASP A06:2025, ASVS 5.0 V2/V5 · → T2 · SPEC: AC-4, EC-2):
  Invalid or boundary-violating monetary inputs are passed into `validatePriceIqd` or `formatPriceIqd`: zero (`0`), negative integers (`-1`, `-5000`), fractional decimals (`15000.5`, `0.5`), non-finite numbers (`NaN`, `Infinity`, `-Infinity`), unsafe integers (`Number.MAX_SAFE_INTEGER + 1`), or non-number values (`"25000"`, `null`, `undefined`).
  **Expected secure behaviour:** Both `validatePriceIqd` and `formatPriceIqd` fail closed by throwing an explicit `TypeError` or `RangeError`—never rounding, truncating, coercing strings, or returning `"0 د.ع"` / `"NaN د.ع"` / decimal strings. Only positive safe integers (`1`, `750`, `25000`) succeed and format as `"1 د.ع"`, `"750 د.ع"`, and `"25,000 د.ع"`.

- **AB-5** (axis: `business_logic` · entry: `src/lib/products.ts#validateCatalog`, `src/lib/products.ts#validateProduct`, `src/components/product-card.tsx#ProductCard`, `src/components/product-details.tsx#ProductDetails` · ref: OWASP A06:2025, ASVS 5.0 V2 · → T2, T3, T4 · SPEC: AC-2, AC-3, AC-5, EC-1, EC-3):
  A malformed catalog dataset (`0`, `9`, or `11` items, or `10` items with duplicate `id` values) or a product with empty/whitespace-only required fields (`name: "   "`, `description: ""`, `imageAlt: " \t"`) is passed to `validateCatalog` / `validateProduct`; or UI cards/details are checked for unauthorized pricing modifiers (discounts, percentages, compare-at/previous prices, taxes, or delivery fees).
  **Expected secure behaviour:** `validateCatalog` throws when item count `≠ 10` or any `id` is duplicated; `validateProduct` throws when any required field is missing or empty after trimming; `/` renders strictly 10 product cards from `PRODUCTS`, and both `ProductCard` and `ProductDetails` display only one fixed `"د.ع"` price per item with zero discounts, strikethrough prices, taxes, or delivery fees.

- **AB-6** (axis: `injection` · entry: `src/lib/products.ts#getProductById`, `src/lib/products.ts#isValidProductId`, `GET /products/[id]` (`src/proxy.ts#proxy`, `src/app/products/[id]/page.tsx#ProductPage`) · ref: OWASP A05:2025, ASVS 5.0 V2/V5 · → T2, T5 · SPEC: AC-6, AC-7, EC-5):
  An attacker sends JavaScript `Object.prototype` property names (`__proto__`, `constructor`, `toString`, `valueOf`, `hasOwnProperty`) as product IDs to `getProductById`, `isValidProductId`, or `GET /products/__proto__` to provoke prototype lookup confusion or runtime `TypeError` (`500`).
  **Expected secure behaviour:** `getProductById` (implemented with strict equality via `Array.prototype.find`, never plain-object property lookup) returns `undefined`, `isValidProductId` returns `false`, `proxy.ts` rewrites the request to `/__not-found` with HTTP `404`, and `ProductPage` triggers `notFound()` with zero `500` errors or prototype property leakage.

- **AB-7** (axis: `injection` · entry: `GET /products/[id]` (`src/proxy.ts#proxy`, `src/app/products/[id]/page.tsx#ProductPage`, `generateMetadata`, `src/components/not-found-view.tsx#NotFoundView`) · ref: OWASP A05:2025, ASVS 5.0 V1/V2 · → T3, T5 · SPEC: AC-7, EC-4):
  An attacker sends XSS payloads or malformed percent-encodings in the product path (`/products/<script>alert(1)</script>`, `/products/%3Cimg%20src%3Dx%20onerror%3Dalert(1)%3E`, `/products/%E0%A4%A`) aiming to inject HTML/script into the rendered response or `<title>`, or crash `decodeURIComponent` with an unhandled `URIError` (`500`).
  **Expected secure behaviour:** `proxy.ts` wraps `decodeURIComponent` in `try/catch` and rewrites both malformed encodings and script payloads to `/__not-found` with HTTP `404`; `NotFoundView` and `not-found.tsx` metadata render fixed static Arabic copy (`"المنتج غير موجود"`) without reflecting any URL segment, parameter, or query string, preventing both XSS and `500` crashes.

- **AB-8** (axis: `injection` · entry: `public/images/products/product-01.svg` … `product-10.svg`, `src/lib/products.ts#validateProduct`, `src/components/product-card.tsx#ProductCard`, `src/components/product-details.tsx#ProductDetails` · ref: OWASP A05:2025, ASVS 5.0 V1/V5 · → T1, T2, T3 · SPEC: AC-3, AC-9, EC-3):
  An attacker or faulty asset supplies an unsafe `imageSrc` (`https://evil.example/x.svg`, `http://localhost/x.svg`, `javascript:alert(1)`, `data:image/svg+xml,<svg onload=alert(1)>`, `../secret.svg`) to `validateProduct`, or a local SVG in `public/images/products/*.svg` contains `<script>`, `on*` event attributes, `<foreignObject>`, or external `http(s)://` links executed when visited directly on the app origin.
  **Expected secure behaviour:** `validateProduct` rejects any `imageSrc` not matching `/^\/images\/products\/[a-z0-9-]+\.svg$/`; all 10 static SVG files under `public/images/products/` contain zero `<script>`, `on*` attributes, `<foreignObject>`, or external `http://`/`https://` URLs; UI renders `<Image unoptimized ... />` solely against validated local SVG paths.

- **AB-9** (axis: `mass_assignment_data_exposure` · entry: `src/lib/products.ts#validateProduct`, `src/lib/products.ts#PRODUCTS`, `src/app/not-found.tsx`, `src/app/products/[id]/not-found.tsx` · ref: OWASP A01:2025, OWASP A10:2025, ASVS 5.0 V16 · → T2, T3, T5 · SPEC: AC-3, AC-7):
  (1) An object containing unexpected extra fields (`{ ...validProduct, adminNote: "secret", discountPercent: 50 }`) is passed to `validateProduct` to test whether unvalidated fields propagate onto the returned `Product` DTO; (2) `PRODUCTS` and `404` responses are inspected for real PII or internal stack traces / file paths.
  **Expected secure behaviour:** `validateProduct` builds an explicit allow-listed `Product` object (`id`, `name`, `priceIqd`, `imageSrc`, `imageAlt`, `description`), dropping any extra properties; `PRODUCTS` contains zero real personal names, real phone numbers, or real street addresses; all `404` error paths return static Arabic copy with zero stack traces, internal filesystem paths, or raw exception messages.

- **AB-10** (axis: `resource_abuse_uploads` · entry: `src/proxy.ts#proxy`, `public/images/products/*.svg` · ref: OWASP API4:2023, ASVS 5.0 V4 · → T1, T5 · SPEC: AC-7, EC-4):
  An attacker sends deeply nested `/products/1/a/b/...` paths, oversized encoded IDs, query parameters (`/products/99?next=https://evil.example`), or rapid bursts (up to 50 requests) to trigger ReDoS, external fetches, disk I/O, or query-string injection into the internal rewrite destination.
  **Expected secure behaviour:** `proxy.ts` applies linear non-backtracking matching (`/^\/products\/([^/]+)$/`), performs synchronous in-memory allow-list checks (`O(10)`), constructs `/__not-found` without carrying over incoming query strings or untrusted path segments, makes zero external network or filesystem calls, and returns deterministic HTTP `404` responses without `5xx` errors; zero file-upload handlers exist and static SVGs remain lightweight.

- **AB-11** (axis: `configuration_secrets_supply_chain` · entry: `next.config.ts`, `src/proxy.ts#proxy`, `src/app/layout.tsx#RootLayout`, `package.json` · ref: OWASP A02:2025, OWASP A03:2025, ASVS 5.0 V12/V14 · → T1, T2, T5 · SPEC: AC-8, AC-9):
  Inspecting configuration, `proxy.ts` header handling, client bundles, and dependencies for hardcoded secrets, payment keys, sensitive `NEXT_PUBLIC_*` variables, `dangerouslyAllowSVG: true`, `remotePatterns`, response header reflection (`NextResponse.next({ headers })`), untrusted `Host` redirects, or unapproved runtime packages.
  **Expected secure behaviour:** Zero secrets, payment keys, or `.env*` secrets exist in tracked files; `next.config.ts` retains `dangerouslyAllowSVG: false` and no `remotePatterns`; `proxy.ts` never reflects request headers onto `NextResponse` and never emits external redirects using `Host`; `RootLayout` sets `<html lang="ar" dir="rtl">` without external font/image/script requests; zero new npm runtime dependencies are added.

## 6. Design & configuration observations (non-blocking)
- **Security headers in `next.config.ts`:** `next.config.ts` does not currently define HTTP security headers (`X-Content-Type-Options: nosniff`, `Referrer-Policy`, `X-Frame-Options` / `Content-Security-Policy` `frame-ancestors`). Because `TASK-001` uses no auth/sessions, no user uploads, and strictly static local SVGs verified free of scripts (`AB-8`), this is not a blocker for `TASK-001` (and a nonce-based CSP would conflict with static prerendering under `cacheComponents: true`). However, adding static response headers (especially `X-Content-Type-Options: nosniff` and `Content-Security-Policy: script-src 'none'` on `/images/products/:path*`) is recommended as a defense-in-depth hardening follow-up if the app is later exposed beyond local pilot testing.
- **Pre-stream `proxy.ts` rewrite URL construction:** When implementing `src/proxy.ts` in `T5`, prefer cloning `request.nextUrl` (`const url = request.nextUrl.clone(); url.pathname = "/__not-found"; url.search = "";`) or `new URL("/__not-found", request.url)` exclusively inside `NextResponse.rewrite(..., { status: 404 })` (never `NextResponse.redirect(...)`), ensuring query parameters and untrusted `Host` values cannot trigger open redirects.
