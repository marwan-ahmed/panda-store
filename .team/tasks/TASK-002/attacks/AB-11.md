# AB-11 — Resource Abuse & Storage Bounds

- **Axis:** `resource_abuse_uploads` (OWASP API4:2023, ASVS 5.0 V4)
- **Target:** `http://127.0.0.1:3000`, `src/lib/cart-storage.ts#parseStoredCart`
- **Evidence source:** `.team/tasks/TASK-002/attacks/probe-results.json` (`ab11_burst`, `ab3_to_ab11_domain_storage`)

## Observed Checks

1. **Live HTTP burst check (`30` concurrent requests <= `50` limit):**
   - `15x GET /cart` + `15x GET /products/cart` completed in `109 ms` with `15x 200` and `15x 404` and zero errors.

2. **Storage size and array-length caps:**
   - `parseStoredCart("x".repeat(70000))` rejected before `JSON.parse` in `0 ms` (`{ items: [], needsRepair: true }`).
   - `parseStoredCart` on a 300-item JSON array scanned only the first `MAX_RAW_STORAGE_ITEMS` (`200`), dropping entry `250` (`{ productId: "2", quantity: 1 }`) and returning `{ items: [{ productId: "1", quantity: 1 }], needsRepair: true }`.

3. **File uploads:**
   - Zero file-upload inputs or handlers exist in the application.

## Conclusion
`localStorage` parsing enforces the `65536`-byte and `200`-item bounds, and the built server handles rapid requests stably with zero upload surface.
