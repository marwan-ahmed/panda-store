# سجل القرارات — panda-store

> ملك المشروع. يضيف المعماري قرارات العمارة (ADR)، وتُسجَّل هنا قرارات قبول المخاطر بنص صاحب القرار. القالب: `.team/templates/DECISION.md`.

## ADR-1 — تخزين الكتالوج الثابت في وحدة TypeScript محلية مع تحقق إلزامي عند التحميل
- **التاريخ:** 2026-11-26      **صاحب القرار:** المحلل والمعماري (بناءً على EXEC_PROMPT.md وAGENTS.md)
- **النوع:** قرار معماري
- **المهمة:** TASK-001
- **السياق:** تتطلب المهمة عرض 10 منتجات بالضبط من بيانات اصطناعية ثابتة بأسعار أعداد صحيحة موجبة بالدينار العراقي، دون قاعدة بيانات أو لوحة تحكم أو تعديل، مع التوافق مع `cacheComponents: true` في Next.js 16 واختبارات Vitest المتزامنة.
- **القرار:** حفظ بيانات المنتجات العشرة كمصفوفة ثابتة للقراءة فقط في `src/lib/products.ts` مفحوصة عند التحميل عبر دوال التحقق (`validateCatalog`, `validateProduct`, `validatePriceIqd`) وصياغة السعر (`formatPriceIqd`)، مع عرض الصفحة الرئيسية `/` بشكل متزامن وتوليد صفحات التفاصيل العشر مسبقاً عبر `generateStaticParams`.
- **البدائل المرفوضة:**
  - قراءة ملف JSON من القرص عند كل طلب عبر `fs.readFile` (يضيف تعقيد I/O غير متزامن دون فائدة لبيانات ثابتة).
  - إنشاء قاعدة بيانات أو نقاط اتصال API للكتالوج (خارج نطاق المهمة صراحةً ويوسّع سطح الهجوم).

## ADR-2 — اعتماد صور SVG محلية ثابتة داخل `public/images/products/` مع `unoptimized` وإبقاء `dangerouslyAllowSVG: false`
- **التاريخ:** 2026-11-26      **صاحب القرار:** المحلل والمعماري
- **النوع:** قرار معماري
- **المهمة:** TASK-001
- **السياق:** يشترط الطلب صوراً محلية اصطناعية خفيفة دون روابط شبكة خارجية أو صور حقيقية، بينما يمنع Next.js 16 افتراضياً تمرير SVG عبر مُحسِّن الصور (`dangerouslyAllowSVG: false`) لتقليل مخاطر حقن السكربتات.
- **القرار:** إنشاء 10 ملفات SVG متجهية ثابتة وخالية تماماً من أي `<script>` أو معالجات أحداث أو روابط خارجية تحت `public/images/products/`، وعرضها عبر `next/image` مع خاصية `unoptimized` وأبعاد ثابتة ونص بديل عربي، مع إبقاء `next.config.ts` دون تفعيل `dangerouslyAllowSVG`.
- **البدائل المرفوضة:**
  - تفعيل `dangerouslyAllowSVG: true` في `next.config.ts` (يزيد سطح المخاطر الأمنية ويعدّل ملف إعداد حساس).
  - استخدام روابط صور خارجية أو تضمين Base64 داخل كود المنتجات (يخالف قيد الصور المحلية أو يضخّم حزمة الصفحة).

## ADR-3 — التحقق المسبق في `src/proxy.ts` مع `notFound()` لضمان حالة HTTP 404 حقيقية مع Cache Components
- **التاريخ:** 2026-11-26      **صاحب القرار:** المحلل والمعماري
- **النوع:** قرار معماري
- **المهمة:** TASK-001
- **السياق:** يفعّل المشروع `cacheComponents: true` و`partialPrefetching: true` في `next.config.ts`. ووفق وثائق Next.js 16 (`streaming.md` و`loading.md`)، فإن استدعاء `notFound()` بعد بدء البث يُبقي رمز الحالة HTTP عند `200`، بينما يتطلب المثال E11 في `EXEC_PROMPT.md` إرجاع حالة `404` للمنتج غير الموجود أو المعرّف المفقود.
- **القرار:** إضافة `src/proxy.ts` على المسارين `/products` و`/products/:path*` للتحقق من المعرّف المفرد بعد فك الترميز بأمان قبل بدء البث؛ وعند عدم تطابقه مع المنتجات العشرة أو نقص المعرّف أو تشوّه الترميز، يُعيد كتابة الطلب داخلياً إلى `/__not-found` بحالة `404` لعرض صفحة عدم الوجود العربية (`src/app/not-found.tsx`)، مع الإبقاء على `notFound()` داخل `src/app/products/[id]/page.tsx` و`src/app/products/page.tsx` كحماية مزدوجة وفي اختبارات الوحدة.
- **البدائل المرفوضة:**
  - تعطيل `cacheComponents` أو `partialPrefetching` في `next.config.ts` (يلغي إعدادات Next.js 16 المعتمدة في المشروع).
  - الاكتفاء بـ `notFound()` داخل `<Suspense>` فقط (يرسل حالة HTTP `200` قبل تحقق عدم الوجود).
  - إرجاع نص أو JSON خام من `proxy.ts` (يفقد الزائر الواجهة العربية ورابط العودة إلى الكتالوج).
